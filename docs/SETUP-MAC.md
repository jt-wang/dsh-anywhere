# Set up the companion on a Mac (Tailcat transport)

中文说明：[SETUP-MAC.zh.md](SETUP-MAC.zh.md).

For an Apple-silicon Mac running DeepSeek Harness (DSH). The phone reaches the Mac through
Tailcat: no VPN app, no public IP, no server to run, at home or away.

Nothing here restarts DSH, opens a firewall port or changes macOS trust. The companion listens only on
`127.0.0.1`; the Tailcat helper is the only way in, and only for phones you paired.

## Install (one command)

With DSH Desktop installed and opened once, run:

```sh
dsh plugin --profile desktop add https://github.com/jt-wang/dsh-anywhere/releases/latest/download/dsh-anywhere-darwin-arm64.tgz
```

No `dsh` on PATH: use the app's launcher
`"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"`. DSH checks the supported versions
(`0.2.0-rc.2`, every 0.2.1 release or pre-release, and every 0.2.2 release candidate or release) while
installing.

DSH loads the new bundle; on its first start the companion creates its private Tailcat configuration in
`~/Library/Application Support/DSHMobile/host/` (a random host ID, a P-256 certificate for `h-<hostId>.dsh.invalid`,
loopback port 19445, access to all DSH projects). `companion.log` there ends with `running <version>` once it runs.
Then open **Settings → Mobile → Pair a phone** in DSH. Remove it with `dsh plugin --profile desktop remove dsh-anywhere`.

[AGENT-INSTALL.md](../AGENT-INSTALL.md) is the same procedure for an AI agent, with checks.

## Update

Run the install command again, then quit and reopen DSH Desktop. Until you do, the old version keeps running. Paired
phones stay paired.

## Pair the phone

[Download the Android app](https://github.com/jt-wang/dsh-anywhere/releases/latest/download/dsh-anywhere.apk) and install it. In DSH, open **Settings → Mobile → Pair a phone** and scan the code with the app. Revoke a phone on the same page.

## What can see what

- Tailscale's public DERP relays carry encrypted WireGuard packets when no direct path exists; they see
  node public keys and traffic sizes, never contents.
- Inside the tunnel the phone still checks the Mac's pinned certificate and uses its own device token.
- An execute grant lets the phone drive DSH agents on this Mac.

## Build and install from source

For development, generative interfaces (`--generative-ui`) or a CLI web host (`--profile web`).

Tools:

- Node.js 24 (`node --version` → `v24.x`), e.g. `brew install node@24`.
- Go 1.27 or later, only to build the Tailcat helper from source (`brew install go`; Go downloads the
  exact pinned toolchain itself).
- Your DSH home: the folder that contains `profiles/web/package.json` (`profiles/desktop` for the DSH Desktop app). Export it, for example
  `export DSH_HOME="$HOME/.dsh"`, after checking the folder exists. It is never guessed.
- `dsh --version` must print a supported version (`0.2.0-rc.2`, a 0.2.1 release or pre-release, or a 0.2.2 release candidate or release); otherwise pass it
  explicitly with `--dsh-version`.

Build, from this repository:

```sh
tools/build-tailcat.sh          # Tailcat helper → host/dist/tailcat/ (and the Android library)
cd host && npm ci && npm run build && cd ..
```

`npm run build` prints `Tailcat helpers: dsh-tailcat-host-darwin-arm64, …` when the helper is in place.
`node tools/pack-bundle.mjs` then makes the one-command package in `build/bundle/`.

Install and activate:

```sh
node tools/install-host.mjs                 # install + create the private Tailcat configuration, print the profile block
node tools/install-host.mjs --activate      # write the reviewed block into the selected profile patch
```

For the DSH Desktop app, pass `--profile desktop` to both commands: the app boots
`$DSH_HOME/profiles/desktop`, and the default profile is `web` (CLI web hosts). `--activate` refuses a profile
that already has `dsh-anywhere` from `dsh plugin add`.

After activation, open **Settings → Mobile** in the DSH app: the page shows host
status, **Pair a phone** (read-only or with task execution), the one-use QR, and paired
devices. The CLI commands below remain available for headless hosts and automation.

- Files go to `~/Library/Application Support/DSHMobile/` (owner-only): `plugin/<version>/` (immutable),
  `host/host.json` with its TLS identity and state, `backups/` (profile backups before every change).
- The first run calls `setup-tailcat`: a random host ID, a P-256 certificate for
  `h-<hostId>.dsh.invalid` generated by Node (no OpenSSL needed), loopback port 19445 (`--port` to
  change), access to all DSH projects (registry mode).
- `--activate` changes only the marked companion block, after a backup and a check that nobody else
  edited the file meanwhile. DSH picks it up by hot reload; if it does not, restart DSH yourself.

Moving from `install-host.mjs`: run `node tools/install-host.mjs --profile desktop --uninstall` first, because the
bundle refuses to start while that profile block exists. Both use the same default configuration, so phones stay paired.

### Check that it runs

```sh
CLI="$HOME/Library/Application Support/DSHMobile/plugin/0.7.2/dist/cli.js"   # use your installed version
CONFIG="$HOME/Library/Application Support/DSHMobile/host/host.json"
node "$CLI" tailcat-status --config "$CONFIG"      # "running": true
```

The CLI comes with the source install (`plugin/<version>/dist/cli.js`); a one-command install has no CLI, so pair
from **Settings → Mobile** and read `host/companion.log`.

### Pair from the command line

Run
`node "$CLI" pair --config "$CONFIG" --tailcat --read all --execute all --qr`
and scan the code in the app within two minutes. Clear the terminal afterwards: the QR is a one-use secret.

Omit `--execute all` for a read-only phone. After pairing the phone connects by itself through Tailcat.

### Manage

```sh
node "$CLI" devices --config "$CONFIG"                       # paired phones
node "$CLI" revoke --config "$CONFIG" --device <deviceId>     # cut a phone off (Tailcat access is removed within seconds)
node tools/install-host.mjs --uninstall                       # remove the profile block; configuration and state stay
```
