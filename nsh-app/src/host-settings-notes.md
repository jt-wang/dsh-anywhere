## Delivery / lifecycle

Read / refresh opens the cards. While opened and foregrounded, the account controller subscribes to `account/watch` and `account/watchExpiry`. Credential changes, stream errors, transport loss and foreground teardown clear identity/details/notices and fence late replies. Foreground/network resume and reconnect rebaseline; ordinary same-generation login progress refreshes details without discarding a presented card. Subscription cancel functions and timers are disposed when inactive or unmounted. No background polling or permanent socket is promised. Account credentials and provider secrets remain on the computer.

Account notice polling is serial and scheduled **after** settlement, using the server's positive `nextPollAfterSeconds` (initial fallback 600 seconds). Local expiry removes list/card/actions without reporting dismissal. A content response does not report `displayed`: the native view waits for a display frame, next task and measured nonzero bounds intersecting the foreground viewport. Offscreen content sends no impression; scrolling into view permits one per notice/lifecycle. Lost event acknowledgements are surfaced without automatic report retries; false acknowledgements invalidate authority. Account CTA retains the card; server consumption does not close an already opened card.

Signout first reads `account/hasRunningAccountTasks`, shows an explicit second confirmation and warns that work can start after the check. Confirmation is credential-generation-fenced locally, not an atomic server account lock. One `account/signOut {client}` call is followed by an authoritative state read even after lost acknowledgement. Failed readback leaves authority cleared. Grant-revocation retry is exclusively host-owned. Sign-in still has the documented desktop callback limitation; no login RPC or bridge was added.

Refresh discards actionable old CUA grants. Preset revision conflict or lost acknowledgement disables more preset writes until refresh; mutations are never replayed automatically. CUA action failure discards the actionable old snapshot and reports uncertain delivery.

**Existing transport limitation outside these owned files:** `dsh.ts:241` silently removes a clean logical-stream `end`, without invoking an end/error callback. The account controller handles the exposed errors, carrier state changes and fresh stream frames, but cannot detect that isolated clean end immediately. Foreground/resume, explicit refresh and subsequent safe notice reads still rebaseline/invalidate as applicable. Full desktop clean-end equivalence needs the transport owner to expose clean termination; this task deliberately did not alter shared transport or add a bridge.

The user-selected settings scope A is unchanged: keyboard shortcuts and desktop update channel remain computer-owned; another module owns phone-local workspace view preferences. This module does not change any of those owners.
